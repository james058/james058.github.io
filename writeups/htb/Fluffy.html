HTB Fluffy Writeup

Recon & Port Scanning

We begin with a full TCP scan to fingerprint exposed services: 


nmap -A -Pn -p- 10.129.232.88

The scan reveals a classic Windows Domain Controller footprint:

  • 53 (DNS)
  • 88 (Kerberos)
  • 389 / 636 (LDAP / LDAPS)
  • 445 / 139 (SMB)
  • 464 (kpasswd)
  • 3268 / 3269 (Global Catalog)
  • 5985 (WinRM)

The certificate CN and SAN values confirm the hostname: DC01.fluffy.htb.

SMB Enumeration

Anonymous listing shows several domain shares, including an interesting IT share. Using valid credentials, we confirm read/write access: 


smbmap -u j.fleischman -p 'J0elTHEM4n1990!' -H 10.129.232.88

Inside the IT share we find:

  • Everything search tool
  • KeePass installer
  • Upgrade_Notice.pdf

Upgrade Notice PDF

The PDF lists several CVEs requiring urgent patching. One stands out: CVE‑2025‑24071, a spoofing vulnerability allowing NTLMv2 hash leakage via malicious .library-ms files inside ZIP archives.

NTLMv2 Hash Capture

We generate a malicious ZIP and upload it to the IT share. With Responder listening, we capture an outbound NTLMv2 authentication attempt.

After cracking the hash, we obtain new credentials:

p.agila / prometheusx‑303

Domain Enumeration (BloodHound)

BloodHound reveals a privilege chain:

  • p.agila ∈ Service Account Managers
  • Service Account Managers → GenericAll over Service Accounts
  • Service Accounts → GenericWrite over ca_svc, ldap_svc, winrm_svc

This enables shadow credential attacks.

Shadow Credentials (Certipy)

We add p.agila to Service Accounts and use Certipy to generate shadow credentials for:

  • ca_svc
  • ldap_svc
  • winrm_svc

We obtain NT hashes for each account.

User Shell

Using winrm_svc NT hash: 


evil-winrm -u winrm_svc -H <NT_HASH> -i 10.129.232.88

We retrieve user.txt.

Privilege Escalation (ESC16)

Certipy identifies ESC16: Security Extension disabled on the CA. This allows UPN manipulation and certificate-based impersonation.

Steps

  1. Change ca_svc UPN → administrator
  2. Request a certificate as Administrator
  3. Restore original UPN
  4. Use the certificate to authenticate as Domain Admin

We obtain administrator.pfx and authenticate as Domain Admin, retrieving root.txt.
